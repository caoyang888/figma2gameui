# 公司内部 UI 制作台：实施与验收

此功能在独立分支；既有 Figma 插件继续可用，不修改主分支。

| 阶段 | 可交付成果 | 验收条件 |
| --- | --- | --- |
| 1. 计划与契约 | 约定用户流程、数据所有权、AI 与导出边界 | 无公司原图或密钥入库，文件格式和首版范围明确 |
| 2. 项目与 AI | Web 工作台、项目资源持久化、模型启用前探测、上传分析及人工审查 | 模型列表可拉取；真实图像探测格式正确才启用；重复上传合并精确重复；错误任务可重试；审查版本可回看 |
| 3. Cocos 导出 | 服务端 Cocos 3.8.8 资源包、单界面及全量、稳定 UUID 和引用校验 | 重复导出一致；两个界面可共享一份资源；Creator 实际导入、打开、重导另作最终门槛 |
| 4. 交接 | 运行文档、样例和端到端回归 | 同事先看预览，仅处理例外，成功导出；说明尚未真实验证的内容 |

## 用户路径

项目 → 导入切图 PNG/JPG/WebP、字体、ZIP；可附参考整图 → 服务器后台分析 → 看预览和异常 → 确认 → 下载。模型设置单列，默认只需配置一次；已有 Figma 设计稿继续走旧插件，未来接入真实文档结构。首版不做细粒度项目权限、图集、多引擎或自动生成业务代码。

## 数据边界

- 数据只在工作台自己的持久卷上；代码库是公开的，不放公司的素材和生产配置。
- 模型入口由部署方配置允许的 HTTPS 根地址。可人工填模型 ID；列出的模型也必须成功识别随机合成图才能启用。不发送生产资产做连通性测试。且不因测试关系授予访问额外外部服务的权限。
- 数据模型：项目、项目内资源、原始上传别名、分析任务与可批准方案、导出资源清单。切图的像素身份、逻辑尺寸和 Creator 资源身份彼此独立。
- AI 提出解释、引用现有资产 ID、建议修复项；后台校验节点、层级、坐标和资源引用。缺图保留明确占位或补传建议，不默默造图。不把 AI 生成内容当作可直接执行的代码。
- Cocos ZIP 必须带预制体、引用资产与相应 meta。单界面和全量共享稳定身份；只能在真实 3.8.8 中打开过之后宣布通过最终 Creator 验收。
